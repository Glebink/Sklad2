# Склад

Один сервис из двух приложений на общей базе Supabase (проект `zayavki`, ref `okgzagezzeeglkyrwbzv`, Франкфурт):

- **Учёт потребления** (`/uchet/`) — заявки на учёт, «Склад», «1С», инвентаризация, сравнение остатков, перемещение. Работает с локальной копией в браузере, синхронизируется с Supabase.
- **Заявки на закупку** (`/zayavki/`) — заявки, позиции, статусы, фото, история. Развивать пока не планируем — без нужды не трогаем.

Вход один на оба приложения. Переключение приложений — кнопка-меню слева в верхней панели («Учёт потребления» / «Заявки на закупку»). Вкладки учёта — строкой в шапке рядом: Учёт · [Склад | 1С] (одна кнопка пополам) · Инвентаризация (только hleb; на телефоне «Инвент.»). Сменщику строка вкладок не показывается; на телефоне в открытой заявке тоже (там «‹» к списку). На телефоне уже 400 px версия в шапке скрыта. Справа — версия и иконка профиля (аккаунт, синхронизация, резервная копия, выход).

Версия **v2.0 до релиза** (не поднимать). Меняется в трёх местах: `APP_VERSION` в `uchet/js/core.js` и `zayavki/app.js`, `CACHE_NAME` в `sw.js`.

## Синхронизация учёта
- Основная — локальная копия: приложение работает без связи. Правки уходят через 3 с после последней; сверка — при возврате в приложение и по сигналу Realtime.
- Если ключ изменился и на устройстве, и на сервере, правки сливаются по последнему общему состоянию (база в `sklad2_sync_base_v1`):
  - списки позиций («Склад», «1С», позиции заявок) — по позиции; количества, изменённые с двух сторон, складываются как разницы; удалённая на одной стороне и не тронутая на другой позиция удаляется, изменённая — остаётся;
  - позиция узнаётся по коду; у кодов-заглушек 1С (один код у разных товаров: `Б210426`, `Б061026`, `ВРЕМЕННЫЙ`…) — по коду + названию + номеру повтора;
  - инвентаризация — по позиции (код + название), а не по номеру строки; список позиций берётся у той стороны, что его обновила;
  - инвентаризация и галочки сливаются и без сохранённой базы: введённое только здесь добавляется, при разных числах — число сервера.
- «Данные расходятся» (красная точка, выбор «мои / сервера») остаётся только для остальных ключей, когда базы нет. Если данные важны — **не нажимать «Оставить данные сервера»**, сначала разобраться.
- Новое устройство (ключ ещё ни разу не синхронизировался) при обмене только забирает данные сервера. Исключение — восстановленная резервная копия: там спрашивает.
- Не сохранилось в браузере (переполнена память) — инвентаризация сразу показывает ошибку.
- Одно приложение — одна вкладка браузера: две вкладки синхронизируются наперегонки.

## Роли и вход
| Роль | Логин | Что может |
|---|---|---|
| requester | hleb | заявки на закупку — создаёт; учёт — всё; только у него: удаление и комментарий заявок, дата заявки, инвентаризация, QR склада |
| boss | boss | заявки на закупку — статусы; учёт — всё |
| shift (сменщик) | sklad | только «Учёт»: своя заявка за сегодня (одна в день), позиции любой заявки за сегодня и вчерашней до 04:00 МСК; подсказки — из каталога сервера |

- Email аккаунтов `логин@zayavki.app`; новый аккаунт — Authentication → Users + строка в `profiles`. Пароли меняет пользователь сам.
- «Сегодня» — по Москве (клиент `todayStr`, сервер).
- QR-вход склада: у hleb кнопка QR в шапке списка заявок. Ссылка `…/uchet/?qr=<токен>#today` → функция `qr-login` выдаёт одноразовый вход за `sklad`. QR действует 72 часа; «Сгенерировать новый» отключает все устройства, вошедшие по старому QR (вход по паролю не отключается). По QR — режим киоска: только заявка текущего дня.

## Безопасность
- Все таблицы под RLS; у роли `anon` (без входа) прав на таблицы и функции нет. Удалять строки `sklad_kv` нельзя.
- Сменщику сервер (`sklad_kv_shift_guard`) разрешает только заявки на учёт по правилам выше; ошибки — по-русски с подсказкой.
- Кнопки в интерфейсе — удобство; защита — на сервере.
- Удаления в базе (`delete`, `drop`, удаление строк из списков) ассистент сам не выполняет: даёт SQL, пользователь запускает в SQL Editor. Остальное ассистент применяет сам. SQL для пользователя писать без одинарных кавычек (`$$…$$`, `array[$$…$$]`): при копировании с телефона ' превращаются в ‘ ’.

## Учёт: заявки
- Слева список заявок (новые сверху, номер — по порядку создания `created`, одинаков на всех устройствах), по центру выбранная заявка. Поиск слева — по номеру, дате, комментарию, названию и коду деталей.
- «+» — заявка на сегодня (сменщик — одна в день). У hleb: дата заявки (задним числом встаёт сверху со следующим номером), комментарий, «⋮» → комментарий / удалить, кружок у номера — зелёный, если отмечены все позиции.
- Пустые заявки удаляются сами через час после создания.
- Таблица «Позиции» сгруппирована по моделям (YGW 4.0 → YGW 5.0 → 9Bot → без модели). Колонка «Шт»: крупное количество, маленьким в углу — остаток 1С; «−»/«+» открывают окно ввода. Галочки «учтено» — личные (у hleb синхронизируются между его устройствами).
- Строка ввода: лупа (раскрывает поиск по заявке), «Деталь» с подсказками (порядок по моделям, остаток 1С справа), количество (пусто = 1), «+». Повторный ввод той же позиции прибавляет количество.

## «Склад» и «1С»
- Одна таблица: код, название; в углу названия — модели (до двух: `model`, `model2`) и остаток 1С. Фильтр по заголовку: Самокаты ▸ модель / Инструменты / Расходники / Одежда / Остальное (+ «Не на складе» и «Остаток < N» в «1С»); выбор хранится на устройстве.
- Связь «Склад ↔ 1С» — по коду, у кодов-заглушек — по коду и названию (`ocName` у позиции склада). Модель одна на пару.
- Позиции на склад добавляются из «1С» кнопкой «+». Количество склада (`qty`) в интерфейсе не используется.
- Остаток 1С вручную не правится — только «⬆ Импорт» файла .xlsx: обновляет остатки имеющихся (ключ строки — код + название, одинаковые строки файла складываются), добавляет новые, обнуляет отсутствующие (с защитой от неполной выгрузки). Названия, модели, категории не меняет.
- У кодов Ninebot `AB.…` числа в названии («(25)», «22-25») — год, не модель: модель по названию для них — только явная метка 9Bot.

## Инвентаризация (пункт меню, только hleb)
- Вкладка «Инвентаризация» в шапке (адрес `#inv`) → слева список инвентаризаций, «+» — новая с датой. Инвентаризация хранит свой снимок 1С (позиции и остатки на момент создания, без повторов код + название). «⟳ Обновить из 1С» берёт текущий список 1С, введённые числа сохраняются.
- Таблица: Код / Наименование (со «Склада», если позиция там есть, иначе из 1С; модели в углу) / 1С / Склад. «Склад» — фактическое количество; пусто = как в 1С. Зелёная строка — по факту больше, красная — меньше, в углу разница. Enter — к следующей строке. Нажатие на «1С» / «Склад» в заголовке — сортировка: по убыванию → по возрастанию → как было («Склад» без числа = как в 1С); выбор хранится на устройстве.
- Строка добавления как в «Учёте»: выбрал деталь (подсказки по названию склада, 1С и коду), ввёл найденное сейчас — число **прибавляется** к «Склад» (нашёл ещё коробку — добавил ещё). Лупа слева раскрывает поиск по таблице. Фильтр — как в «1С».
- «Итого»: «Списать» (в 1С больше) / «Выдать» (по факту больше), порог расхождения в штуках, «⬇ Excel». «В учёт» (для «Списать») — заявка за сегодня с комментарием «Списание инвента»; если такая за сегодня уже есть — её список заменяется. Из инвентаризации не уводит, на кнопке — «✓ Заявка № N создана/обновлена».
- Остатки 1С инвентаризация не меняет: списание в 1С — вручную.
