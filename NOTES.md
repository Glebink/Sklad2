# Склад

Один сервис из трёх приложений на общей базе Supabase (проект `zayavki`, ref `okgzagezzeeglkyrwbzv`, Франкфурт):

- **Учёт потребления** (`/uchet/`) — заявки на учёт, «Склад», «1С», инвентаризация, сравнение остатков, перемещение. Работает с локальной копией в браузере, синхронизируется с Supabase.
- **База знаний** (`/baza/`) — ячейки с названиями и файлами-инструкциями (Word, Excel, PDF, картинки). Смотрят все, меняет только hleb.
- **Заявки на детали** (`/zakaz/`) — приложение ремонтника (роль repair): свои заказы деталей; собирает их hleb во вкладке «Заказы» учёта.

Вход один на все приложения. Переключение приложений — кнопка-меню слева в верхней панели (значок куба со стрелкой, без подписи; в меню «Учёт потребления» / «База знаний»). Вкладки учёта — строкой в шапке рядом: [Учёт | Заказы] · [Склад | 1С] (по одной кнопке пополам) · Инвентаризация («Заказы» и «Инвентаризация» — только hleb; уже 1200 px — «Инвент.», на телефоне «Заказы» и «Инвентаризация» — значками; у «Заказов» в углу — число новых). Все половинки равные, обе пары одной ширины; у кого нет «Заказов», «Учёт» — на всю кнопку. Сменщику строка вкладок не показывается; на телефоне в открытой заявке тоже (там «‹» к списку). На телефоне уже 370 px версия в шапке скрыта (у hleb — уже 430 px). Справа — версия и иконка профиля (аккаунт, синхронизация, резервная копия, выход).

Версия **v2.0 до релиза** (не поднимать). Меняется в четырёх местах: `APP_VERSION` в `uchet/js/core.js`, `baza/app.js`, `zakaz/app.js`, `CACHE_NAME` в `sw.js`.

## Синхронизация учёта
- Основная — локальная копия: приложение работает без связи. Правки уходят через 3 с после последней; сверка — при возврате в приложение и по сигналу Realtime.
- Если ключ изменился и на устройстве, и на сервере, правки сливаются по последнему общему состоянию (база в `sklad2_sync_base_v1`):
  - списки позиций («Склад», «1С», позиции заявок) — по позиции; количества, изменённые с двух сторон, складываются как разницы; удалённая на одной стороне и не тронутая на другой позиция удаляется, изменённая — остаётся;
  - позиция узнаётся по коду; у кодов-заглушек 1С (один код у разных товаров: `Б210426`, `Б061026`, `ВРЕМЕННЫЙ`…) — по коду + названию + номеру повтора;
  - инвентаризация — по позиции (код + название), а не по номеру строки; список позиций берётся у той стороны, что его обновила;
  - инвентаризация и галочки сливаются и без сохранённой базы: введённое только здесь добавляется, при разных числах — число сервера.
- «Данные расходятся» (красная точка, выбор «мои / сервера») остаётся только для остальных ключей, когда базы нет. Если данные важны — **не нажимать «Оставить данные сервера»**, сначала разобраться.
- Новое устройство (ключ ещё ни разу не синхронизировался) при обмене только забирает данные сервера. Исключение — восстановленная резервная копия: там спрашивает.
- Не сохранилось в браузере (переполнена память) — инвентаризация сразу показывает ошибку.
- Несколько вкладок на одном устройстве: память браузера общая, и когда одна вкладка записывает данные, остальные сразу их забирают (событие `storage`). Раньше «отстающая» вкладка затирала чужие правки своей старой копией.

## Роли и вход
| Роль | Логин | Что может |
|---|---|---|
| requester | hleb | учёт — всё; база знаний — админ; только у него в учёте: удаление и комментарий заявок, дата заявки, инвентаризация |
| boss | boss | учёт — всё; база знаний — просмотр |
| repair (ремонтник) | свой у каждого: dan (тестовый), alex, ivan, lev | только `/zakaz/`: свои заказы деталей; учёт и база знаний закрыты (переадресация, на сервере — ограничивающие политики) |
| shift (сменщик) | sklad | «Учёт»: своя заявка за сегодня (одна в день), позиции любой заявки за сегодня и вчерашней до 04:00 МСК; подсказки — из каталога сервера; база знаний — просмотр |

- Email аккаунтов `логин@zayavki.app` (домен — от убранных «Заявок на закупку», не менять); ремонтников hleb заводит сам: профиль → «Аккаунты» (создать, имя, пароль, отключить/включить — функции `accounts_list`, `account_create`, `account_set_password`, `account_set_name`, `account_set_disabled`, проверяют `app_login() = hleb`). Пароль ремонтника хранится копией для hleb (`account_passwords`, читают только функции; решение пользователя 24.11). Отключение — `banned_until` = 2999 (не `infinity`: сервер входа его не читает), заказы остаются. Остальные аккаунты — Authentication → Users + строка в `profiles` (`role`, `name`, `login`). Имя ремонтник только видит. Пароли меняет пользователь сам.
- «Сегодня» — по Москве (клиент `todayStr`, сервер).
- Регистр в логине и пароле не важен: логин приводится к строчным, пароль отправляется строчными (пароли на сервере задавать строчными: `crypt($$пароль$$, gen_salt($$bf$$))`); если не подошёл, а в набранном есть заглавные, — вторая попытка как набран (старые пароли).
- Вход только по логину и паролю. QR-вход склада убран 30.10. Сменщику сервер отдаёт данные только в сессии, начатой входом по паролю (`sklad_session_ok`, ограничивающая политика на `sklad_kv`).

## Безопасность
- Все таблицы под RLS; у роли `anon` (без входа) прав на таблицы и функции нет. Удалять строки `sklad_kv` нельзя.
- Сменщику сервер (`sklad_kv_shift_guard`) разрешает только заявки на учёт по правилам выше; ошибки — по-русски с подсказкой.
- Кнопки в интерфейсе — удобство; защита — на сервере.
- Удаления в базе (`delete`, `drop`, удаление строк из списков) ассистент сам не выполняет: даёт SQL, пользователь запускает в SQL Editor. Остальное ассистент применяет сам. SQL для пользователя писать без одинарных кавычек (`$$…$$`, `array[$$…$$]`): при копировании с телефона ' превращаются в ‘ ’.

## Учёт: заявки
- Слева список заявок (новые сверху, номер — по порядку создания `created`, одинаков на всех устройствах), по центру выбранная заявка. Карточка: № и дата; число позиций и автор; внизу «⋮» и комментарий (до двух строк). Левый столбец (`--list-w`) — 273–400 px. Поиск слева — по номеру, дате, комментарию, названию и коду деталей.
- «+» — заявка на сегодня (сменщик — одна в день). У hleb: дата заявки (задним числом встаёт сверху со следующим номером), комментарий, «⋮» → комментарий / удалить, кружок у номера — зелёный, если отмечены все позиции.
- Пустые заявки удаляются сами через час после создания.
- Таблица «Позиции» сгруппирована по моделям (YGW 4.0 → YGW 5.0 → 9Bot → без модели). Колонка «Шт»: крупное количество, маленьким в углу — остаток 1С; «−»/«+» открывают окно ввода. Галочки «учтено» — личные (у hleb синхронизируются между его устройствами).
- Строка ввода: лупа (раскрывает поиск по заявке), «Деталь» с подсказками (порядок по моделям, остаток 1С справа), количество (пусто = 1), «+». Повторный ввод той же позиции прибавляет количество.

## «Склад» и «1С»
- Одна таблица: код, название; в углу названия — модели (до двух: `model`, `model2`) и остаток 1С. Фильтр по заголовку: Все / Самокаты ▸ модель / Инструменты / Расходники / Одежда / Остальное (+ «Не на складе» и «Остаток < N» в «1С»); выбор хранится на устройстве.
- Связь «Склад ↔ 1С» — по коду, у кодов-заглушек — по коду и названию (`ocName` у позиции склада). Модель одна на пару.
- Ключевые слова для поиска (поле `keys` позиции склада, через запятую: «шина, покрышка, резина передняя») — в окне правки позиции «Склада», вписывает только hleb. Позиция находится, если все слова запроса есть в названии вместе с одной из фраз («шина 10» → «Покрышка 10"» со словом «шина»). Работает везде: подсказки «Учёта», сменщика, ремонтников (каталог сервера несёт `keys`), инвентаризации, поиск по «Складу», «1С», заявке; у позиций 1С, инвентаризации и заявок — слова связанной позиции склада. В подсказках такие совпадения — после совпадений по коду и названию.
- Позиции на склад добавляются из «1С» кнопкой «+». Количество склада (`qty`) в интерфейсе не используется.
- Остаток 1С вручную не правится — только «⬆ Импорт» файла .xlsx: обновляет остатки имеющихся (ключ строки — код + название, одинаковые строки файла складываются), добавляет новые, обнуляет отсутствующие (с защитой от неполной выгрузки). Названия, модели, категории не меняет.
- У кодов Ninebot `AB.…` числа в названии («(25)», «22-25») — год, не модель: модель по названию для них — только явная метка 9Bot.

## Заказы деталей (ремонтник → hleb)
- Ремонтник (`/zakaz/`): слева свои заказы (№ по порядку, дата, статус), справа выбранный; на телефоне два экрана. «+» — новый черновик. Строка добавления как в «Учёте»: подсказки по каталогу `potreblenie_catalog_v1` (поиск — `search.js`, остаток 1С справа), количество, «+»; можно своим текстом. Повтор той же детали прибавляет количество. Правки уходят на сервер через 0,6 с.
- «Отправить» — заказ появляется у hleb. Дописывать и править можно, пока заказ новый или собирается (то же правило на сервере: RLS и триггер `parts_orders_guard` — статус и список сборки меняет только hleb). Черновик (не отправленный) можно удалить.
- Сборка (◷): hleb нажимает «Сборка» (или вводит «выдано» у нового заказа) — работает со своей копией списка (`hleb_items`), правки ремонтника сами в неё не попадают. Ремонтник поправил — у кнопки обновления (справа от «Перенести в учёт») «!», на карточке «! изменён», в счётчике вкладки +1. Нажатие — окно изменений (+ добавил / − убрал / ~ было → стало): «Принять» (список сборки по новому, «выдано» сохраняется, не больше «просят») или «Отказать» (список ремонтника возвращается к принятому). Ремонтник видит «ждут подтверждения кладовщика». На ✓ / ~ / ✕ список сборки становится списком заказа; непринятые правки отклоняются (с вопросом).
- Корзина на карточке заказа у hleb — удалить заказ (с вопросом; ремонтник его тоже больше не видит).
- hleb: вкладка «Заказы» (`#orders`). Слева заказы: новые сверху (давние выше), затем остальные — свежие сверху; на карточке имя, кружок статуса, «Учтено» / «Не учтено». Справа: статус — ◷ Сборка / ✓ Готово / ~ Частично / ✕ Отмена; таблица Код / Наименование (остаток 1С в углу) / Просят / Выдано. «Выдано» по умолчанию = сколько просили (при отмене — 0), строка, где выдано частично, — жёлтая, где не выдано ничего — красная (у ремонтника так же).
- «Перенести в учёт» (после «Готово» / «Частично»): выданное — в последнюю сегодняшнюю заявку на учёт (нет — создаётся), позиция — с кодом и названием «Склада», если она там есть. Сначала на сервер ставится `accounted_at` (без связи перенос не идёт — не задвоится), затем заказ больше не правится, на кнопке «✓ Учтено …».
- Ремонтник видит статус и «выдано», но не «Учтено». Новые заказы и статусы приходят сразу (Realtime).
- Профиль ремонтника (кнопка справа): фото (нажатие — выбрать, сжимается до 256 px; «Убрать фото»), логин, имя. Фото стоит на кнопке профиля; у hleb — кружком на карточке и в заголовке заказа (без фото — первая буква имени).

## Инвентаризация (пункт меню, только hleb)
- Вкладка «Инвентаризация» в шапке (адрес `#inv`) → слева список инвентаризаций, «+» — новая с датой. Инвентаризация хранит свой снимок 1С (позиции и остатки на момент создания, без повторов код + название). «⟳ Обновить из 1С» берёт текущий список 1С, введённые числа сохраняются.
- Таблица: Код / Наименование (со «Склада», если позиция там есть, иначе из 1С; модели в углу) / 1С / Склад. «Склад» — фактическое количество; пусто = как в 1С. Зелёная строка — по факту больше, красная — меньше, в углу разница. Enter — к следующей строке. Нажатие на «1С» / «Склад» в заголовке — сортировка: по убыванию → по возрастанию → как было («Склад» без числа = как в 1С); выбор хранится на устройстве.
- Строка добавления как в «Учёте»: выбрал деталь (подсказки по названию склада, 1С и коду), ввёл найденное сейчас — число **прибавляется** к «Склад» (нашёл ещё коробку — добавил ещё). Лупа слева раскрывает поиск по таблице. Фильтр — как в «1С».
- «Итого»: «Списать» (в 1С больше) / «Выдать» (по факту больше), порог расхождения в штуках, «⬇ Excel». «В учёт» (для «Списать») — заявка за сегодня с комментарием «Списание инвента»; если такая за сегодня уже есть — её список заменяется. Из инвентаризации не уводит, на кнопке — «✓ Заявка № N создана/обновлена».
- Остатки 1С инвентаризация не меняет: списание в 1С — вручную.

## База знаний (`/baza/`)
- Слева ячейки (как заявки в «Учёте»), справа — файлы выбранной ячейки строками (значок типа, имя, размер); на телефоне два экрана. Поиск по названию ячейки и файла.
- Нажатие на файл — просмотр на весь экран (`view.html?cell=…&path=…`): на ПК в новой вкладке, в приложении на главном экране — в том же окне (кнопка «‹» назад к ячейке; новая вкладка на iPhone открылась бы в Safari без входа).
  - Excel — данные без оформления и картинки: сетка с буквами столбцов и номерами строк (закреплены), объединённые ячейки, листы — вкладками внизу. До 20 000 строк на лист. Картинки SheetJS не читает — их достаём из файла (zip, JSZip): плавающие (`xl/drawings`, привязка к ячейкам), в ячейке нового Excel (`xl/metadata.xml` + `xl/richData`), в ячейке WPS (`DISPIMG`, `xl/cellimages.xml`). На листе с картинками ширина столбцов и высота строк — как в файле. Картинки EMF/WMF браузер не показывает.
  - Word — постранично (docx-preview), на телефоне страница сразу по ширине экрана. Фигуры Word (стрелки, рамки) не показываются — для них сохранять в PDF.
  - PDF и картинки — в браузере его собственным просмотрщиком (ссылка на час, `createSignedUrl`); в приложении на главном экране и без связи — здесь же (pdf.js).
  - Масштаб только содержимого, как Ctrl + колесо: Ctrl + колесо / щипок на тачпаде, два пальца, на ПК кнопки − 100 % +. Вбок — полоса, Shift + колесо, перетаскивание мышью.
- hleb: «+» — новая ячейка; «⋮» — переименовать / выше / ниже / удалить (вместе с файлами); «+ Файл» (можно несколько); у файла ↑ ↓ ⬇ 🗑. boss и sklad — только просмотр (без кнопок; скачать через просмотрщик браузера могут — так решили 06.11).
- Форматы: .docx, .xlsx, .pdf, .png/.jpg/.webp/.gif. Старые .doc/.xls — пересохранить в .docx/.xlsx.
- Права на сервере: `kb_cells` и бакет `kb` читают все вошедшие (сменщик — только в сессии по паролю), меняет только `app_login() = hleb`.
- Открытые файлы запоминаются в кэше браузера (`sklad2-kb-files`), список ячеек — на устройстве: без связи ранее открытое видно.
- Файлы: `common.js` (общее), `app.js` + `style.css` (список), `view.html` + `view.js` + `view.css` (просмотр).
