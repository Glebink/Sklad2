# Склад

Один сервис из двух приложений на общей базе Supabase (проект `zayavki`, ref `okgzagezzeeglkyrwbzv`, Франкфурт):

- **Учёт потребления** (`/uchet/`) — учёт, склад, 1С, сравнение остатков, перемещение. Работает с локальной копией в браузере, синхронизируется с Supabase.
- **Заявки на закупку** (`/zayavki/`) — заявки, позиции, статусы, фото, история.

Переключение между ними — меню в левом углу шапки. Вход один на оба сервиса.

## Файлы
```
index.html        переход в последний открытый раздел
auth.js, auth.css общий вход и клиент Supabase
sw.js             общий service worker (кэш, офлайн)
manifest.json, icon-192.png, icon-512.png
uchet/            index.html, app.js, style.css
zayavki/          index.html, app.js, style.css
```

## Публикация (GitHub Pages)
1. Репозиторий `sklad2`, все файлы в корень с сохранением папок.
2. Settings → Pages → Deploy from a branch → `main`, `/ (root)`.
3. Адрес: `https://glebink.github.io/sklad2/`. Прямые: `/uchet/`, `/zayavki/`.

Публичный (anon) ключ Supabase в `auth.js` хранить в репозитории можно: доступ ограничивают правила RLS на сервере. Пароли и ключи `service_role` в репозиторий не кладём.

## Версия
Одинаково меняем в трёх местах: `APP_VERSION` в `uchet/app.js`, `APP_VERSION` в `zayavki/app.js`, `CACHE_NAME` в `sw.js`. Правило: каждое обновление +0.1.

## Вход
Логин и пароль аккаунтов Supabase (`requester`, `boss`, далее по ролям). Галочка «Запомнить» снята — сессия только в этом окне. Вход в одном разделе действует и в другом.
Смена пароля: в приложении заявок (меню аккаунта) или Supabase → Authentication → Users.

## Данные
| Что | Где |
|---|---|
| Заявки, позиции, каталог, история, фото | таблицы заявок и бакет `photos` |
| Учёт, склад, 1С, список перемещения, остатки Бестужевской | таблица `sklad_kv` (строка на ключ) |
| Последние 20 версий каждого ключа | таблица `sklad_kv_log` |
| Сортировка, фильтры, журнал правок | только в браузере устройства |

Ключи в `sklad_kv` названы по-старому (`potreblenie_*`), в браузере те же данные лежат как `sklad2_*`. Файл резервной копии использует старые имена, поэтому копии совместимы со старым складом.

## Синхронизация учёта
- Локальная копия основная: приложение работает без связи.
- Автоматически: правки уходят через 20 секунд после последней, при возврате в приложение и при сообщении сервера (Realtime) идёт сверка.
- Если данные изменились и на устройстве, и на сервере, приложение ничего не затирает и показывает «данные расходятся». Меню ⋮ → Синхронизация → выбрать: оставить данные сервера или мои.
- Меню ⋮ → Синхронизация: статус, ручной обмен, автосинхронизация, аккаунт, резервная копия, выход. Точка на ⋮: красная — ошибка или конфликт, жёлтая — есть неотправленные правки.
- Откат: в `sklad_kv_log` лежат предыдущие версии (Supabase → Table Editor).

## Первый запуск учёта на новом адресе
1. Войти.
2. Меню ⋮ → Синхронизация → «Восстановить» → выбрать файл резервной копии из старого склада.
3. Сверка: если пишет «данные расходятся», выбрать «Оставить мои данные».

## Переезд со старых адресов
1. Проверить новый сервис на тестовом устройстве: вход, учёт, склад, 1С, заявки.
2. Сделать резервную копию в старом складе, восстановить в новом.
3. На телефонах и ПК удалить старые иконки (склад и заявки) и установить заново с `https://glebink.github.io/sklad2/` (iPhone: Safari → Поделиться → На экран «Домой»). Старые PWA с нового адреса не обновятся: адреса разные.
4. Старые репозитории `sklad` и `zayavki` оставить на неделю как запасной вариант, затем убрать. Данные заявок в Supabase от этого не меняются.

## Безопасность
- Таблицы под RLS: читать и писать могут только вошедшие пользователи, удалять строки `sklad_kv` нельзя.
- Роли пока не разграничены в учёте: любой вошедший видит и правит данные склада. Ограничения по ролям (сменщица, ремонтники, начальник) делаются отдельным этапом.
